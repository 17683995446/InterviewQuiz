🎯

职责分离

每层只关注自己的职责，UI层负责展示，ViewModel层负责状态管理，Domain层处理业务逻辑

🔄

依赖倒置

通过接口抽象，Domain层不依赖具体实现，便于单元测试和模块替换

🧪

易于测试

各层可独立测试，通过Mock对象可以轻松验证业务逻辑的正确性

展示应用启动、题目筛选、作答等核心业务流程

1 应用启动流程 

flowchart TD
    A([🚀 启动应用]) --> B[创建 Application]
    B --> C[初始化 Hilt DI]
    C --> D[注入 SecurityManager]
    D --> E[执行安全检测]
    E --> F{Root/模拟器?}
    F -->|是| G[⚠️ 记录警告日志]
    F -->|否| H[✅ 继续启动]
    G --> H
    H --> I[创建 MainActivity]
    I --> J[设置 FLAG_SECURE]
    J --> K[创建 Compose UI]
    K --> L[注入 HomeViewModel]
    L --> M[调用 loadQuestions]
    M --> N[初始化 UseCases]
    N --> O[从 Repository 获取数据]
    O --> P[更新 UI State]
    P --> Q([✅ 显示主界面])

2 题目筛选流程 

flowchart TD
    A([👤 用户选择筛选条件]) --> B[selectCategory / selectDifficulty]
    B --> C[更新 HomeUiState]
    C --> D[触发 applyFilters]
    D --> E[获取过滤条件]
    E --> F{分类筛选?}
    F -->|是| G[🔍 过滤指定分类]
    F -->|否| I{难度筛选?}
    G --> H
    I -->|是| J[🎯 过滤指定难度]
    J --> H
    I -->|否| H{搜索查询?}
    H -->|是| K[📝 模糊匹配]
    H -->|否| L[📋 返回全部]
    K --> L
    L --> M[更新 filteredQuestions]
    M --> N[🔄 UI 重组]
    N --> O([✅ 显示结果])

3 题目作答流程 

flowchart TD
    A([👤 点击题目卡片]) --> B{卡片状态?}
